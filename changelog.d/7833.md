---
synopsis: Pin package revisions with the `revisions` project field
packages: [cabal-install]
prs:
issues: 7833
---

The new `revisions` field of `cabal.project` pins a package version to a
specific `.cabal` file revision, written in the notation Stack uses:
`pkg-1.2.3@rev:N` selects the revision by number (the `x-revision` field, the
original upload being revision 0) and `pkg-1.2.3@sha256:HASH` by the hash of
the `.cabal` file text, as reported in `plan.json`. A pin only applies when the
solver picks that package version; it is an error when the package version
exists but none of its revisions match the pin.

`cabal freeze` now also records a pin for every package in the plan whose
`.cabal` file is a revision, so that later revisions of the package cannot
change the frozen plan without freezing the whole index with `index-state`.
