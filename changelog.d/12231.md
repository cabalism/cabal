---
synopsis: "Fix cabal run not recognising a target given after `--`"
packages: [cabal-install]
issues: 12231
---

`cabal run` used to tell target strings from the executable's arguments by
counting the strings around the `--` separator. When everything followed the
separator, as in `cabal run -- my-test-suite --randomize`, the count made the
target zero-length and the target name was handed to the executable, which
rejected it as an unexpected argument. This worked in cabal-install 3.16.1.0
and regressed in 3.18.1.0.

`cabal run` now classifies every argument that does not look like a flag by
asking whether it names a target in the project, and derives the split from
that:

- The target may be given on either side of `--`.
- Only one target is accepted; arguments are no longer absorbed as extra
  targets.
- When only one component can be run (an executable, a test suite or a
  benchmark), no target is needed.
- Naming the same component more than once, explicitly as in `cabal run foo
  foo` or by way of a wildcard as in `cabal run all:exes`, now warns and runs
  it rather than being silently accepted.

Flags are never probed, so a flag that happens to share a name with a component
is not mistaken for a target. Where the split is not obvious, `cabal run` now
says why: when a string that names a component is passed to the executable as
an argument, when a string before `--` does not name a target, and when a
target is repeated.
