---
synopsis: Notice when a `file+noindex` repository changes
packages: [cabal-install]
prs: 0000
issues: 9136
---

cabal keeps an index of a `file+noindex` repository in a `noindex.cache` file
and used not to build it again once it existed. After a package was added to the
directory or removed from it, cabal went on using the old index until the cache
was deleted or `cabal update` was run. A package that had been added was unknown
to the solver, and a package that had been removed made the build stop with a
file error.

cabal now builds the index again when a `.tar.gz` file, a `.cabal` file or the
`preferred-versions` file in the directory is added, removed or modified.
Project commands also take a change to those files as a reason to solve again.

The format of `noindex.cache` has changed. The first time a cache written by an
older cabal is read, cabal warns that it could not parse it and builds it again.
